## 4. 利润明细动态分组

保留六列：

`归类｜费用项｜计费基准｜费率占比｜金额｜规则来源`

保留现有：

- `profitBasisToggle`；
- 计算基准切换；
- 规则来源和外部链接；
- 规则说明页面；
- 现有公式与费用规则。

### 4.1 单项归类

某归类只有一个实际配置费用项时：

- 只显示一行；
- 不显示“XX 合计”；
- 不显示展开箭头；
- 不创建折叠明细；
- 不允许折叠。

例如：

`商品｜商品采购成本｜计费基准｜费率占比｜金额｜规则来源`

“收入”只有商品售价时，只显示：

`收入｜商品售价`

不得显示“收入合计”或“商品售价合计”。

### 4.2 多项归类

某归类有两个或以上实际费用项时：

- 显示合计行；
- 显示费用明细；
- 默认展开；
- 支持折叠；
- 合计金额必须等于明细金额之和。

### 4.3 计数口径

- 按实际配置或实际返回项目数动态判断；
- 禁止按归类名称硬编码；
- 已配置但金额为 `0` 的项目仍算一项；
- 未配置、未返回的项目不计数；
- 切换计费基准只改变基准显示和结果，不改变分组结构。

至少测试：单项非零、单项零、两项、零值混合、三项以上、收入单项、基准切换。

## 5. 汇率高可用

### 5.1 目标

刷新汇率时应几乎总能返回可用于利润计算的数据，不能因一个网站故障让利润模块不可用。

### 5.2 同一快照

一条汇率快照必须同时保存：

- MYR/CNY；
- MYR/USD；
- 抓取时间；
- 生效日期；
- 数据来源；
- 是否使用历史有效值回退；
- 校验状态或原始响应摘要。

MYR/CNY 和 MYR/USD 必须同批次、同一快照生效。

### 5.3 来源和失败切换

至少配置：

- 1 个主来源；
- 2 个备用来源。

要求：

- 每个来源独立适配；
- 设置连接和读取超时；
- 对可恢复异常进行有限重试；
- 主来源失败自动切换备用来源；
- 校验空值、日期和异常范围；
- 单个来源失败不能直接让整个请求失败。

### 5.4 持久化

有效汇率必须写入数据库，不得只依赖：

- 进程内缓存；
- `/tmp`；
- 单机临时文件。

至少保存当前有效快照、历史快照、来源、最近成功时间和最近失败信息。

### 5.5 定时刷新

- 后台每日主动刷新；
- 执行时间可配置；
- 任务失败不覆盖最近有效值；
- 多实例环境防重复执行。

### 5.6 手动刷新

点击刷新后：

1. 按顺序尝试主来源和备用来源；
2. 任一成功就保存新快照；
3. 全部在线来源失败时返回数据库最近一次有效快照；
4. 页面显示该快照更新时间；
5. 只有数据库从未保存有效快照时才显示真正不可用。

保留现有自动汇率、手动汇率、刷新、恢复自动和页面布局。手动汇率不能被后台任务强行覆盖。

## 6. 竞品监控

### 6.1 入口迁移

从商品中心移除：

- 直接竞品入口；
- 间接竞品入口；
- 对应侧边链接和筛选。

统一放到：

**竞品监控 → 竞品商品**

### 6.2 以商品链接为核心

不建立独立可见的“竞品店铺”模块。

新增竞品只强制填写：

- 商品链接；
- 直接竞品 / 间接竞品。

其他资料允许留空后补。

### 6.3 当前采集方式

当前仓库没有可靠的 TikTok 马来西亚公开商品链接读取能力。本轮按手动维护实现：

- 链接可点击打开；
- 不提供不可靠的自动读取按钮；
- 不伪造读取结果；
- 后续有合法稳定数据服务时另行开发自动采集。

### 6.4 商品级字段

每条链接独立维护：

- 商品名称；
- 商品链接；
- 直接/间接类型；
- 商品价格；
- 销量；
- 商品评分；
- 评论数；
- 可售状态；
- 本土发货 / 跨境发货；
- 图片；
- 备注；
- 最后更新时间。

### 6.5 店铺级联动字段

按相同店铺名称默认联动：

- 店铺名称；
- 店铺评分；
- 是否明星店铺；
- 品牌卖家 / 普通卖家。

以下不联动：

- 本土发货 / 跨境发货；
- 商品名称、价格、销量、商品评分、评论数和可售状态。

### 6.6 联动规则

1. 相同店铺名称默认归为同一内部组。
2. 不提供独立店铺管理页面。
3. 修改店铺评分、明星店铺或卖家类型时，同组商品同步显示。
4. 修改某条商品的店铺名称时，只把当前链接移动到新店铺组。
5. 原组其他商品保持不变。
6. 所有字段均允许手动修改。

后端可增加内部 `CompetitorSellerGroup` 或等价模型，但前端不得新增用户未要求的竞品店铺模块。

### 6.7 历史记录

商品级监控字段变化时自动生成商品快照：

- 价格、销量、商品评分、评论数、可售状态、发货类型。

店铺级字段变化时生成店铺组历史：

- 店铺评分、明星店铺、卖家类型。

值未变化时不重复生成。名称和备注普通修改不强制生成监控快照。

## 7. 自有店铺管理

页面位置：

**商品中心 → 数据维护 → 店铺管理**

### 7.1 字段

- 店铺名称；
- 平台；
- 市场/国家；
- 是否启用；
- 创建时间；
- 更新时间。

默认：

- 平台：`TikTok Shop`；
- 市场：`马来西亚`。

平台和市场允许修改。

### 7.2 名称和生命周期

- 店铺名称必填；
- 全系统唯一；
- 修改店铺名称只更新显示名称，已有 SKU 关联不变；
- 停用后，该店铺商品不参与商品列表售价和利润范围；
- 停用不删除资料，也不改变原“参与列表计算”开关；
- 重新启用后恢复原状态；
- 没有关联 SKU 的店铺可删除；
- 已有关联 SKU 的店铺只能停用。

### 7.3 关联关系

- 一个 SKU 可关联多个店铺；
- 一个店铺可关联多个 SKU；
- 相同 SKU 编码视为同一商品；
- 不同 SKU 编码不自动合并；
- 库存继续按 `SKU + 仓库` 管理，不按店铺复制。

## 8. SKU 基础资料和店铺商品

### 8.1 SKU 字段

新增或补充：

- SKU 编码；
- 商品名称；
- 商品图片；
- 类目；
- 单件采购成本 CNY；
- 包装重量 g；
- 默认达人佣金；
- 是否启用。

新增 SKU 只强制 SKU 编码和商品名称，其余允许后补。资料不完整时利润显示“待完善”。

### 8.2 SKU 编码

- 全系统唯一；
- 没有库存、出入库和店铺关联时可修改；
- 已产生业务数据后不能在普通编辑中直接改码；
- 如未来支持换码，应使用专门迁移操作。

### 8.3 共享字段

商品名称、图片、类目、采购成本、包装重量、默认达人佣金属于 SKU，在所有店铺共享。

### 8.4 店铺商品表格

商品编辑页采用可增删表格，每个店铺一行：

`店铺名称｜商品售价｜商品链接｜店铺专属达人佣金｜参与列表计算｜操作`

店铺名称必须从“店铺管理”选择，不能在商品编辑页任意输入新店铺。

必填：

- 店铺名称；
- 商品售价。

允许留空：

- 商品链接；
- 店铺专属达人佣金。

### 8.5 佣金

- 店铺专属佣金优先；
- 未设置时继承 SKU 默认佣金；
- `0%` 是有效数据，表示没有达人佣金；
- 空值表示未设置；
- 两级都为空时该店铺利润显示“待完善”。

### 8.6 参与列表计算

不使用“上架状态”控制主列表统计，改为明确开关：

**参与列表计算：是 / 否**

同时满足以下条件才参与：

1. 店铺启用；
2. 店铺商品开关为是；
3. 利润必要资料完整。

关闭后资料保留，但不计入主列表范围。

## 9. 商品列表

保持一个 SKU 一行。

主列：

`商品图片｜商品名称 / SKU｜店铺售价｜毛利｜毛利率｜保本 ROI｜可用库存｜操作`

不展示：

- 状态列；
- 类目列；
- 采购成本列；
- 包装重量列；
- 上架状态列；
- 独立店铺数量列。

顶部筛选：

`启用中｜已停用｜全部`

默认显示启用中。已停用商品可重新启用。

库存列只显示可用库存；实际在库、在途和仓库分布进入现有库存详情。

### 9.1 店铺售价

- 一家店铺：`RM18.90`
- 多店同价：`RM18.90 · 2个店铺`
- 多店不同价：`RM18.90–RM22.90 · 3个店铺`

### 9.2 利润指标

显示：

- 广告费前毛利；
- 广告费前毛利率；
- 保本 ROI。

三项必须调用利润试算的同一套后端规则、费用版本和汇率。禁止前端复制另一套计算公式。

实际广告费用只在测算页面填写和计算，不进入商品列表基础利润。

### 9.3 多店铺范围

多店结果不同则显示范围，例如：

- 毛利：`RM5.20–RM8.60`
- 毛利率：`27.5%–36.8%`
- 保本 ROI：`2.10–2.80`

只统计启用店铺中开启“参与列表计算”的店铺商品。

### 9.4 待完善

缺少售价、采购成本、包装重量、类目、达人佣金或其他必要参数时：

- 不显示 `0`；
- 显示“待完善”；
- 点击或悬停提示缺失字段。

部分店铺完整时：

- 正常显示可计算店铺范围；
- 标注 `X家店铺待完善`；
- 只有全部不可计算时才统一显示“待完善”。

### 9.5 行内展开

点击店铺售价、毛利、毛利率或保本 ROI，在当前 SKU 行下方展开店铺明细，不打开弹窗。

明细列：

`店铺名称｜售价｜佣金比例｜毛利｜毛利率｜保本 ROI｜待完善项目｜操作`

不展示上架状态。

### 9.6 操作

只保留：

`编辑｜测算｜删除/停用`

- **编辑**：打开 SKU 基础资料和多店铺资料。
- **测算**：进入多店铺对比测算页，同时比较所有符合条件店铺；点击某店铺查看完整费用明细。页面临时修改默认不回写商品档案。
- **删除/停用**：无库存、无出入库、无店铺关联且无其他业务引用时才允许删除；否则只能停用。

按钮统一叫“测算”，不要使用“利润测算”或“利润试算”。

## 12. API 原则

1. 提供自有店铺读取、新增、编辑、启用、停用和受限删除接口。
2. 提供 SKU 店铺商品读取、添加、编辑和移除接口。
3. 商品列表利润摘要由后端统一计算和返回，前端不得重新实现公式。
4. 摘要应包含售价、毛利、毛利率、保本 ROI 的最小值/最大值、可计算店铺数、待完善店铺数、缺失字段、汇率快照和费用规则版本。
5. 多店铺测算接口返回各店铺摘要和完整费用明细。
6. 竞品联动、快照判断和快照去重由后端处理。
7. SKU 与多店铺资料保存应使用事务，避免部分成功。
