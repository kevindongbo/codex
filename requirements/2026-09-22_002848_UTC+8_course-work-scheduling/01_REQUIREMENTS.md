## 3. 已确认规则

1. 系统自动生成正式安排，不设管理员发布审批；符合条件者全部安排，不设人数上限或轮班分配。
2. 参考图片只提供节次时间，不复制图片中的课程。课程来自每个人的上传结果。
3. 周一至周日；周末二选一工作，默认周六；可批量设置多个周，也可单周改为周日。
4. 每个人有独立账号，可以上传适用于多个周次的课表，至少支持20周；默认打开实际当前周。
5. 本人可以检查识别结果；原图作为原始凭证保存。左侧分设“原始凭证”和“工作安排”入口。
6. 成员修改本人安排必须填写原因或去向，提交直接生效，无审批。
7. 超级管理员可修改全员安排，标注选填，可选择不显示修改标注。
8. 所有有效成员可查看全员工作安排和请假标记。沿用此前明确的范围：原图、课程详情、请假原因只对本人和超级管理员可见；“大家都能看到”指团队安排。
9. 用户授权本文件剩余默认规则由开发者决定，不再逐项询问。

当前日期落在学期外时仍显示当前自然周，提示“当前不在已配置学期”，不跳回旧学期或自动安排全员。可切换学期、任意周和回到本周。

## 5. 原始凭证页面与识别流程

R02/R03：普通成员仅看自己的记录，超级管理员可按成员筛选全员。列表字段：缩略图、提交人、上传时间、适用日期/周次、识别状态、确认状态、版本、操作。

支持 JPG/PNG/WebP，一次1—10张，每张不超过10MB且解码像素不超过2500万；后端验证真实格式并限制解码资源，不只信 MIME。原文件不可改写，存储 SHA-256、原文件名、大小、上传者、上传时间；缩略图和识别用压缩图另存，不能替换原图。存储于私有目录或私有对象存储，不得落入公开 MEDIA_URL。

流程：选择图片和适用周次/周末工作日 → 原图保存 → 异步识别 → 原图与12×7校对网格并排 → 本人校正 → 确认并生成安排。适用周默认本周，可多选、连续周、全学期。多图先各自校对；重叠周必须明确选择一份完整结果，不能隐式合并或最后写入覆盖。

识别输出仅需星期、起止节次或明确时间、可选课程名、可疑区域及识别提示。教师、教室不是排班必要字段。系统提示必须说明图片文本是待识别数据，不执行图内指令；不访问图片中的链接。

仅周一至周五截图不能说明周末没有课。校对页必须让成员检查七天，选择的周末工作日也要明确确认有课/无课。识别器不能根据“没有识别到文字”直接认定无课；模糊、裁切、缺列、无法定位的格子记为未确认。84格全部确认后才允许发布；提供“确认剩余格子均无课”快捷操作并显示涉及范围。

后台识别状态为 queued → processing → succeeded/failed；succeeded仅表示得到候选结果。确认状态独立为 draft/confirmed/archived。识别失败可重试或在原图旁手工标课。没有模型配置时仍能上传原图并手动校对，界面明确“自动识别未配置”，不能假装OCR成功。

采用数据库任务队列和独立 worker 管理命令，避免阻塞 Web 请求；不新增 Redis/Celery 依赖。任务具有租约、心跳、最大尝试次数3次；暂时性超时/429/5xx退避重试，格式错误和鉴权错误直接失败。任务重启后可恢复过期租约，旧任务结果不得回写到已更换的草稿版本。

复用 AIProviderConfig 的加密配置和 AIInvocationLog，新增由超级管理员选择的课表识别模型配置；需实际验证视觉输入和结构化输出，文本连接测试通过不算验收。默认每人最多1个运行中识别任务、每小时10次新识别，整组织并发2个；失败重试受相同预算控制。密钥仅在服务端。模型输出须经过白名单 schema、节次范围及时间校验。

确认发布不再审批。原图永久关联已确认版本；已确认结果修改时生成新版本，老版本可追溯。默认没有物理删除入口；未确认草稿可归档，已被排班引用的版本不能删除。存储容量及长期保留策略列入运维，不自动清理凭证。

## 6. 自动排班与调整规则

R04/R05：首次确认课表后自动成为排班参与人，普通已有ERP账号不因未上传课表自动加入。超级管理员可启用/停用参与人；停用不抹除历史。人员按姓名、用户ID稳定排序，同名显示账号辅助区分。

每人每周保存一份已确认完整课表版本，包含84格和该周周末工作日。没有已确认版本的周为“未提交”，不算有空；新上传尚未确认时，原已确认版本继续有效。保存时展示本次将新增/替换的周，替换要求明确点击确认。

每节基础状态按顺序计算：不是参与人→不纳入；无该周已确认课表→unknown；非选定周末日→rest；有课→class；其余→work。课程只是上班资格的来源，不需要在公共表公开课程名。

个人调整覆盖基础状态，管理员调整优先于个人调整，最终显示与人数统计只取同一条最终状态。优先级为管理员有效调整 > 本人有效调整 > 基础状态。停用账号的未来格不安排工作；历史格保留快照。

R06：本人可整天或多选节次设为 leave（请假）或 out（外出办事，计为不在岗），原因/去向必填，去除首尾空格后2—500字。公共表显示姓名及“请假/外出”标签，原因不下发给其他成员。提交立即生效；允许撤销本人调整并恢复基础状态，撤销也需原因。本人不能改别人，不能覆盖管理员调整；界面提示联系管理员。

超级管理员可给任意人设置 work/leave/out/rest，或清除调整恢复基础状态；原因选填，“显示调整标注”默认勾选，可关闭。关闭只隐藏公共界面“人工调整”标记，不能隐藏请假状态、伪造人数或取消后台审计。已有课程/未确认课表上强制排班时，展示冲突提示并要求该次明确确认，后台记录 force=true。本人无强制排班权限。

时间已开始的节次仅超级管理员可修正；成员可以修改尚未开始的节次和未来日期。整天请假如果当天部分节次已过，仅作用于剩余未开始节次，并在提交前明确展示。选择周末工作日变化重新计算对应周未来基础格，保留请假与管理员覆盖；不得修改已开始格。

重新识别、换课表、多周覆盖、周末切换都不能清空有效请假/人工调整。覆盖后发生课程冲突时管理员覆盖继续有效并向本人和管理员提示。撤销调整恢复的是最新基础状态，不是调整前过期快照。

确认课表与批量更新在事务中完成，任一周版本冲突整批不写入；返回冲突周供刷新。已过去的周只读，普通成员不得通过上传覆盖历史；超级管理员使用专门的历史修正操作和记录。

## 7. 工作安排页面

新增顶层“团队排班”模块，左侧仅“工作安排”“原始凭证”两个主要入口；设置放在管理员可见的页内按钮。默认工作安排/本周，全员可读。新模块独立加载，不绑定当前仓库，不暴露采购或库存数据。

桌面：列为周一至周日及日期，行为12节及起止时间。每格首行显示“上班N人”，其下排列姓名；请假/外出分组显示，休息/有课/未知人数放次级详情。姓名过多超过6人折叠为“查看全部N人”，弹层完整查看，人数不得因折叠改变。有课人员不计入上班；未提交人员显示在顶部“待提交”名单，不能混为0人上班。

顶部：本周范围、学期/周次、上一周/下一周/回到本周、成员筛选、仅看本人、状态图例。高亮今天；跨午夜和周一切换按服务器返回的业务日期更新默认周，用户主动查看历史/未来时不强制跳页。

桌面1366/1440/1920宽度下七列和时间列适配容器，无整页横向滚动；姓名换行、不横排无限拉长。移动端390/430宽度改为单日纵向节次列表，七日按钮分两行，保留周导航，不把七列挤成不可读小字。字体正文14—16px、辅助文字至少12px，状态同时用文字与颜色，支持键盘操作和清晰焦点。

原始凭证页面桌面为左原图/右校对，移动端上下排；预览可缩放。请求失败保留未保存编辑并可重试，离线时只读且显示最后同步时间。新增安排更新成功后立即重取当前周；页面可见时每30秒检查 revision，返回窗口立即刷新，隐藏时暂停轮询。

## 8. 数据结构

新增模型可集中于 `backend/apps/erp/scheduling_models.py`，在 models.py 中导入供Django发现；避免继续扩张库存服务文件。所有业务实体以 UUID 主键、organization 外键、创建/更新时间为基础，服务端验证跨实体组织和用户一致性。

| 模型 | 必需字段与约束 |
|---|---|
| ScheduleTerm | name、first_monday(Date)、week_count(20—52)、timezone、periods(JSON，12个合法且不重叠时间段)、locked_at；组织内学期日期不重叠，使用组织级锁防并发创建 |
| ScheduleParticipant | user、active、effective_from(Date)；组织+user唯一；初次确认加入，停用事件保留 |
| TimetableEvidence | owner、uploaded_by、private_file、sha256、original_name、content_type、size、pixel_width/height、archived_at；原文件不可变；索引组织+owner+created_at |
| TimetableImport | owner、term、evidence(FK)、state、draft_grid、selected_weeks、weekend_day、revision、confirmed_at；网格不允许缺格或越界；多个图片各有import |
| TimetableRecognitionJob | import、input_revision、status、attempts、lease_until、heartbeat_at、provider、sanitized_error、candidate_grid；同import+input_revision仅一个有效任务 |
| MemberWeekPlan | owner、term、week_index、week_start(Date)、confirmed_grid(JSON84格)、weekend_day(sat/sun)、evidence、source_import、revision；组织+owner+week_start唯一；变更追加不可变版本快照 |
| MemberWeekPlanVersion | plan、version、grid、weekend_day、evidence、actor、created_at；plan+version唯一，禁止更新删除 |
| WorkScheduleCell | owner、date、period(1—12)、base_status、effective_status、plan_version、revision、period_start/end快照；组织+owner+date+period唯一，索引组织+date+effective_status |
| ScheduleOverride | owner、date、period、authority(self/admin)、status(work/leave/out/rest)、reason、show_annotation、actor、revoked_at、revision；每人每格每authority仅一个有效覆盖；恢复为撤销覆盖而非伪造状态 |
| ScheduleMutation | actor、idempotency_key、request_hash、response摘要；组织+actor+key唯一，禁止缓存包含原图/密钥的数据 |

使用现有 AuditLog 记录上传/确认/替换/周末调整/请假/撤销/管理员修改；原图正文不写入日志，私有原因不得写入普通成员可读审计日志。可在专有版本/覆盖表保留私有原因，通用日志只存ID和动作，超级管理员查看私有历史仍需后端鉴权。

状态变化调用 bump_sync_revision，避免GET写入或每格触发大量全量同步；事务提交后一次通知。计数与展示读取持久化最终安排，由后端统一计算，前端不重写业务公式。

## 9. API 约定

所有接口前缀 `/api/scheduling/`，复用现有登录鉴权，必验有效账号和内部组织。采用独立权限类：全员读公共安排、本人写个人数据、超级管理员管理全员；不要求给成员开启catalog、warehouse、audit权限。普通admin/manager角色不等同 is_superuser。

| 方法/路径 | 语义 |
|---|---|
| GET context/ | 业务日期、本周、学期列表、时间模板、当前用户能力、revision |
| GET/POST terms/；PATCH terms/{id}/ | 学期查询/管理；写仅超级管理员，锁定后禁止改起始日和时间模板 |
| GET/PATCH participants/ | 管理员管理参与人，公共成员名字来自排班响应，不暴露账号密码资料 |
| GET/POST evidence/ | 按本人范围分页、multipart上传；管理员可指定owner |
| GET evidence/{id}/content/ | 本人/超级管理员鉴权后流式读图，Cache-Control: private,no-store；无公开链接 |
| POST imports/ | evidence_id、term_id、week_indices、weekend_day；创建识别草稿 |
| POST imports/{id}/recognize/；GET jobs/{id}/ | 入队返回202和job_id；轮询状态，不返回供应商密钥或原始错误 |
| GET/PATCH imports/{id}/ | 读取/校正draft_grid和适用周；PATCH必须revision |
| POST imports/{id}/confirm/ | revision、expected_week_revisions、replace_existing布尔；原子发布，返回更新周次、plan revisions和schedule_revision |
| POST imports/{id}/archive/ | 归档，不删凭证和历史计划 |
| GET plans/?week_start=YYYY-MM-DD | 本人详情；管理员可指定owner，不允许普通成员读取他人课程 |
| POST plans/weekend/ | week_starts、sat/sun、expected_revisions；批量/单周更改，仅未来格重算 |
| GET board/?week_start=YYYY-MM-DD | 公共七日12节、每格上班/请假/外出成员与计数、待提交名单；不含课程名/原因/图URL |
| POST adjustments/ | target_user（普通成员只能本人）、dates/periods、status、reason、show_annotation、expected_revisions；普通成员仅leave/out |
| POST adjustments/{id}/revoke/ | 理由、revision；本人只能撤销self，管理员可撤销任意覆盖 |
| GET history/?owner=… | 本人仅本人，管理员全员；包含私有调整原因和版本，不开放给团队公共表 |

批量修改/确认携带 Idempotency-Key，同key同payload重放返回原结果，不重复排班；同key不同payload返回409。对相关周计划和格子事务加锁，revision不符409，无任何部分提交。输入错误400，未登录401，无权限403或对象不可见404，超限429，模型不可用返回明确状态；不得把失败伪装成空课表。API日期以ISO格式，输出时区固定，所有服务端状态必须可序列化和测试。

原图认证读取在浏览器通过带鉴权fetch取得blob展示，关闭预览释放object URL。Nginx不对私有目录提供直出，存储供应商的内部地址不得返回客户端。
