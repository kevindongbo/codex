# 1. 仓间调拨：异常关闭原因改为可选

## 1.1 业务含义不变

异常关闭仍然表示：

> 对已经确认发出的、最终未能正常到达目的仓的运输异常数量做最终结案。

不是撤销调拨，不是把货退回来源仓，也不是补收到目的仓。

例如：来源仓发出 100，目的仓收到 80，剩余 20 异常关闭后：

- 来源仓不会恢复 20；
- 目的仓不会增加 20；
- 调拨在途减少 20；
- 调拨记录保留实收 80、异常关闭 20；
- AuditLog / 历史仍可追溯；
- 相同幂等请求重试不得重复处理。

## 1.2 V4 对 V3 的覆盖

V3 之前要求保存异常原因；V4 最新要求改为：

**异常原因允许不填。**

前端：

- 去掉 `required`；
- 文案显示“异常原因（可选）”；
- 可使用 placeholder：`可不填写`；
- 提交时节点不存在也不能抛裸 TypeError。

后端：

- `reason` 必须 `required=False`；
- 必须 `allow_blank=True`；
- 空值统一存空字符串或项目约定的空值，不得阻止业务动作；
- 审计仍必须记录操作人、调拨单、SKU、异常关闭数量、时间、幂等键/业务结果；原因为空不影响审计。

## 1.3 幂等规则绝对不能删除

当前 V3 实现分支已经给 `closeTransferException()` 增加 `idempotency_key`。V4 不允许为了“原因可空”而删除幂等校验。

异常关闭请求继续必须包含：

- `idempotency_key`
- `quantities`
- `reason`（允许空）

重复提交同一个调拨 + 同一组异常数量时不得产生第二次库存变化。

## 1.4 “结束调拨”剩余异常结案

为了避免同一业务出现两个互相矛盾的输入规则：

- 行级/部分“异常关闭”原因可选；
- “结束调拨”把全部剩余数量一次性异常关闭时，原因同样可选。

但“结束调拨”仍保留二次确认，因为它会一次性关闭整张调拨单所有剩余在途。

# 2. 仓间调拨商品明细：必须真正可展开

## 2.1 当前用户问题

调拨列表中的“商品明细”看起来像折叠摘要，但实际点不开，无法查看完整 SKU。

V4 要求：

- 不能只显示前两条文本再写“等 N 项”；
- 必须存在真正的展开/收起交互；
- 展开后显示每一条调拨商品；
- 点击区域必须明确、键盘可访问、不与行内其他按钮冲突。

## 2.2 单 SKU

只有 1 个 SKU 时直接显示：

```text
[商品图片] 商品名称
           SKU
           × 35
```

无需折叠。

## 2.3 多 SKU

2 个及以上 SKU 时默认显示摘要，例如：

```text
[第一款商品图片] 商品名称 / SKU × 35
共 7 项  ▾
```

展开后显示全部：

```text
[图片] 商品 A
       SKU-A
       × 35

[图片] 商品 B
       SKU-B
       × 25

[图片] 商品 C
       SKU-C
       × 10
```

再次点击可收起。

## 2.4 技术实现

优先使用原生 `<details><summary>`；也可用按钮 + state，但必须真正绑定事件。

禁止继续使用：

```text
等 7 项
```

却没有可展开内容。

# 5. 全仓加权日均出库业务规则继续执行 V3，不得改回旧算法

本轮 UI 修复不得破坏 V3 已确认公式。

继续使用：

- Q3/Q7/Q15/Q30 = 同一 ERP SKU 所有仓库真实销售出库总量；
- 只计 `SHIPMENT + MANUAL_OUTBOUND`；

- 报损、盘亏、调整、调拨、采购、入库、锁定/释放等不算销量；

```text

(3×W3 + 7×W7 + 15×W15 + 30×W30)
```

禁止改回“各周期先除天数再加权”。

默认 40/30/20/10 只是默认值，分母必须动态计算，不能硬编码 9.3。

# 10. V3 主力仓与补货公式全部继续生效

本轮前端修复不得破坏以下 V3 规则：

- 页面仍按当前仓查看；
- 需求侧使用全仓数据；
- 库存侧只用 SKU 主力仓；
- 无主力仓时可以展示信息，但不得给正式建议补货/紧急度/最迟下单；
- 有主力仓后只在主力仓补货页显示；
- 可售天数 = 主力仓可用 ÷ 全仓加权日均，不含在途；
- 补货库存位 = 主力仓可用 + 主力仓已确认在途；
- 其他仓库存不能抵扣主力仓需求；
- lead time 优先历史完整收货 P80，其次首次收货 P80，最后人工 fallback；
- 目标覆盖默认 30，可清空；
- 目标覆盖模式与固定安全库存模式互斥；
- 目标覆盖模式不得额外叠加旧 safety/service/margin；
- 未达到触发点建议补货必须为 0；
- 起订量、整箱数都可空；
- UI 统一使用“起订量”，不得继续显示 MOQ；
- 先应用起订量，再应用整箱向上取整；
- 用户可编辑复核周期取消，后台固定每日检查 + 页面关键事件实时重算；
- 后端是计算唯一真值，前端不得维护另一套不同公式。

详细公式和 Case A-K 必须阅读 `01_INHERITED_V3_FULL_REQUIREMENTS.md`，不能只读本节摘要后开工。
