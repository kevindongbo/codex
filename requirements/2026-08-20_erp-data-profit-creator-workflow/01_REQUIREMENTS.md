## 3. 需求一：部分收货调拨结束后在途归零

### 3.1 业务规则

调拨剩余量继续使用：

```text
remaining = planned_quantity - received_quantity - exception_closed_quantity
```

调拨处于 `in_transit` 或 `partially_received` 且 `remaining > 0` 时必须计入目的仓在途。

用户明确执行“结束调拨”后：

- 弹窗列出每个 SKU 的计划、已收、已异常关闭和本次待关闭数量。
- 必须填写异常原因并二次确认。
- 本次待关闭数量固定为每个 SKU 的全部剩余量，只读且不可修改；如果只关闭部分数量，必须走原有的“异常关闭部分数量”入口。
- 前端只提交异常原因和 `idempotency_key`；后端必须锁定调拨及行记录后重新计算全部剩余量，不能信任浏览器提交的数量。
- 在一个数据库事务中将全部剩余量计入 `exception_closed_quantity`。
- 同步减少目的仓对应 SKU 的 `StockBalance.in_transit`。
- 不增加目的仓 `on_hand`。
- 不恢复来源仓 `on_hand`。
- 最终状态改为 `completed_with_exception`；中文统一显示“已完成（有异常）”。
- 在途来源、库存列表、顶部指标和补货库存位刷新后立即移除该调拨剩余量。
- 同一 `idempotency_key` 与相同请求内容重复提交时，返回第一次成功的同一结果，即使调拨已经进入终态；不得再次减少在途。
- 同一键但请求内容不同返回 HTTP 409；不同键再次操作终态调拨也返回 HTTP 409。
- 收货与结束调拨并发时必须通过行锁串行化；后取得锁的一方基于最新数量重新校验，不能产生超收、负数或在途不一致。
- 写入操作人、原因、各 SKU 关闭前后数量及请求标识的审计日志。

### 3.2 接口与复用要求

- 优先在现有 `StockTransferViewSet` 和 `close_stock_transfer_exception()` 上扩展“结束全部剩余”动作。
- 可以新增明确的 `complete-with-exception` action，但不得复制调拨过账逻辑或创建第二套模型。
- 普通“异常关闭部分数量”入口可保留；“结束调拨”必须是独立、清楚的最终动作。
- 已 `received`、`cancelled` 或 `completed_with_exception` 的调拨不能以新的请求键再次结束；同键重试按前述幂等规则返回原结果。

### 3.3 历史数据

- 不得通过通用 data migration 自动把所有 `partially_received` 调拨视为已结束。
- 对 `TR-20260729-1510` 只能在用户确认实际短少后，通过新页面动作或带组织、调拨单号范围的 dry-run 管理命令关闭剩余 35。
- 正式修复前备份数据库；修复后只读核对该调拨各行、目的仓在途和来源合计。

### 3.4 验收

- 95 件计划、已收 60、结束剩余 35 后：`received=60`、`exception_closed=35`、`remaining=0`。
- 目的仓只增加实际收到的 60，短少 35 不进入在库。

## 7. 需求五：广告返点、真实 ROI/CPA 与配置持久化

### 7.1 广告返点配置

- “计算配置”新增全局默认 `advertising_rebate_percent`，范围 0–100，默认 0。
- 全局返点属于组织共享 working config；保存命名策略时同时进入该策略快照。当前 working config 与命名策略仍是两类独立记录：保存策略捕获当前配置，激活策略把策略快照写入当前 working config。
- 每个试算 SKU 可选填独立返点覆盖值；留空使用全局值。
- SKU 覆盖值只有 JSON `null` 才表示继承全局；显式 `0` 表示覆盖为 0% 返点，不能被当成未填写。
- SKU 覆盖值属于本次试算输入，不自动写入组织共享 working config。
- 保存到商品利润表时，必须保存该 SKU 实际采用的返点值和来源（全局/单独覆盖）。

### 7.2 计算公式

先按现有三种广告输入得到返点前广告成本：

当前计算器一行代表一个 SKU 的一次销售/一次转化，广告归因收入沿用后端现有 `item_price`（MYR），不包含买家支付运费，也不得改用店铺总 GMV。定义：

```text
r = advertising_rebate_percent / 100
USD_PER_MYR = 1 MYR 可兑换的 USD（沿用现有 usd_per_myr）

ROI 模式：返点前广告成本(MYR) = item_price(MYR) ÷ 输入 ROI
CPA 模式：返点前广告成本(MYR) = 输入 CPA(USD) ÷ USD_PER_MYR
广告占比模式：返点前广告成本(MYR) = item_price(MYR) × 输入百分比 / 100
```

再计算：

```text
返点金额 = 返点前广告成本 × 返点比例
实际广告成本 = 返点前广告成本 × (1 - 返点比例)
真实 ROI = 广告成交金额 ÷ 实际广告成本
真实 CPA = 返点前 CPA × (1 - 返点比例)
广告后净利润 = 广告前毛利 - 实际广告成本
```

- ROI、CPA 和广告占比三种模式在存在有效广告输入时都使用 `item_price ÷ 实际广告成本` 计算真实 ROI。
- 真实 CPA 只在 CPA 模式显示，公式为 `输入 CPA(USD) × (1-r)`；ROI 和广告占比模式显示“不适用”，不得反推 CPA。
- 只有返点前广告成本大于 0、且 100% 返点使实际广告成本变为 0 时，真实 ROI 显示“∞/无需付费”；未填广告数据仍显示“暂无数据”，不得除零报错。
- 未填写广告数据时，继续只展示广告前毛利，不伪造 ROI、CPA 或净利润。
- 所有中间计算使用 `Decimal`；沿用后端 `ROUND_HALF_UP`，每个 SKU 的 MYR 金额在现有金额边界舍入到 0.01 后再汇总，多 SKU 总计必须等于各 SKU 展示金额之和。

### 7.3 结果展示

费用明细和商品利润表至少显示：

```text

广告返点比例
广告返点金额
实际广告成本

```

不得只因模型和函数存在就宣称完成。

修复要求：

- `/profit-calculator/config/`、`/strategies/`、`/working-config/` 和汇率请求分别加载、分别显示错误；一个失败不能抹掉其他已成功数据。
- working config 修改后防抖保存；保存失败保留用户页面输入并支持点击重试。
- working config 使用 `revision`、ETag 或等价乐观锁；更新必须携带读取版本，冲突返回 HTTP 409 并提示刷新/合并，不能静默覆盖另一成员的新配置。
- 页面完成首次配置加载前，不得用默认值触发自动保存。
- F5 后恢复组织共享配置，包括广告返点。
- 同组织其他有权限成员刷新后看到相同配置。
- 命名策略保存、激活、另存、覆盖和删除继续单独存在；策略标签刷新后不消失。
- 激活命名策略与 working config 自动保存必须定义顺序并使用同一版本控制，不能互相覆盖。
- SKU 名称、售价、成本、达人佣金、广告输入和 SKU 独立返点不自动共享，只有显式保存到商品利润表后才持久化。

## 8. 需求六：达人管家

### 8.1 导航

- 顶部主导航新增独立“达人管家”，与商品中心、仓配中心、数据分析、利润试算同级。
- 第一版是内部 CRM，不自动抓取达人数据，不自动发送邀约。

### 8.2 达人档案

达人档案只强制要求“达人名称/昵称”；其他字段均允许留空并以“资料待完善”状态保存。

建议字段：

```text
平台、账号名、主页链接
国家/市场、语言
联系方式
粉丝量、标签、类目
负责人
合作状态
备注
是否归档
```

不得把达人联系方式、备注或非公开数据暴露给其他组织。

- 所有达人列表、详情和导出接口要求 `creator_view`；无权限请求返回 403，不能仅在前端隐藏菜单。
- 联系方式、私人备注等敏感字段只返回给同时具有 `creator_view` 的本组织成员；审计日志记录字段名、对象 ID 和变更摘要，不复制完整电话、邮箱或私人备注。
- 导出功能必须执行与页面相同的组织和能力校验。

### 8.3 合作管理

支持：

- 关联达人、店铺、商品/SKU；
- 合作阶段：待联系、已联系、洽谈中、寄样中、待发布、已发布、已完成、暂停；
- 佣金比例、固定费用等合作条件，可留空；
- 寄样商品、数量、物流单号、寄出/签收状态；
- 视频/直播链接、计划发布时间、实际发布时间；
- 跟进记录、下次提醒时间和负责人。

### 8.4 业绩与归因

只允许两类来源：

- 用户手工录入达人带来的订单数、成交件数和 GMV；
- 平台正式授权接口返回的达人/联盟订单归因。

无法确认来源时标记“未归因”。系统不得因视频发布时间与销量上涨接近而自动认定达人带货。

所有业绩记录显示数据来源、录入/同步时间和操作人。

### 8.5 权限与删除

- 具有 `creator_view` 的同组织成员可以查看。
- 创建和修改要求 `creator_edit`；创建人只能编辑自己创建的达人及其子记录。
- 管理员/主账号可编辑、归档全部记录。
- 合作、寄样、内容、跟进和归因子记录继承达人档案的对象权限，不能通过子接口绕过父对象权限。
- 已被合作、寄样、内容或业绩引用的达人，即使主账号也不得永久删除，只能归档。
- 只有完全未被引用的达人允许永久删除；仅主账号可执行，必须二次确认并记录审计日志。

## 9. 需求七：商品利润表与版本化试算记录

### 9.1 新页面

- 利润试算模块新增独立“商品利润表”页面。
- 用户完成计算后点击“保存到商品利润表”。
- 一个“利润方案”只对应一个 SKU，商品利润表的一行就是一个方案。
- 一次多 SKU 试算按 SKU 创建多个方案/版本，并通过同一个试算批次关联；不能把多个 SKU 塞进同一个方案后只显示一行。

### 9.2 主表字段

至少显示：

```text
商品图片
商品名称 / SKU
店铺（可选）
方案名称
售价、商品成本
达人佣金
广告返点
广告前毛利 / 毛利率
实际广告成本
广告后净利润 / 净利率
真实 ROI / CPA
规则版本、汇率日期
保存人、保存时间
操作
```

支持商品、SKU、店铺、方案名称和状态筛选；第一版方案状态至少包含“有效”和“已归档”。

### 9.3 最新结果与历史版本

- 同一 SKU/方案主表只显示最新保存结果。
- 每次重新计算并保存生成新版本，不覆盖旧版本。
- “历史版本”可查看每次输入、配置、汇率、费率版本和结果。
- “查看/复现原结果”直接展示历史输入与历史结果快照，不调用当前规则，不产生新版本。
- “按当前规则重新计算”把指定历史版本的业务输入加载回试算页，但使用当前后端权威汇率、费率和规则；保存时生成新版本，并展示新旧规则版本、汇率和结果差异。
- “保存新版本”更新当前方案的最新结果。
- “另存为方案”创建新的稳定方案 ID 和独立方案行，适用于不同售价或广告方案；不得用可能重复的方案名称充当唯一标识。

### 9.4 持久化数据

复用现有利润计算器，并使用以下明确关系（具体类名可遵循仓库风格，但语义不能改变）：

- `ProfitCalculationBatch`：一次保存操作，属于组织，保存幂等键、请求哈希、创建人和时间。
- `ProfitPlan`：一个 SKU 的一个独立方案，属于组织和批次，可选关联店铺/SKU，保存方案名称、状态和创建/更新人；主表一行。
- `ProfitPlanVersion`：属于一个 `ProfitPlan`，保存递增版本号、完整原始输入快照、后端结果快照、汇率快照和规则版本；创建后不可 PATCH 或单独 DELETE。
- SKU 外键允许为空，但方案和版本必须保留当时的 SKU 编码、名称和图片快照，避免商品归档后历史不可读。
- 至少建立 `(plan, version_number)` 唯一约束；创建新版本时锁定方案行，不能并发生成重复版本号。

具体命名可遵循仓库现有风格，但不得只把最后一次结果存在浏览器 `dataset` 或 `localStorage`。

### 9.5 一致性与幂等

- 保存接口只接收原始试算输入、目标方案动作和 `idempotency_key`；后端必须在事务内调用权威计算器重新计算并保存，数据库不得把浏览器提交的净利润、ROI、CPA 或费用金额当成权威结果。
- 如果需要“先计算、后保存”两步接口，也只能使用后端签名且不可篡改、短时有效的计算令牌；不能信任前端回传结果 JSON。
- 数据库对 `(organization, idempotency_key)` 建唯一约束，并保存规范化请求哈希。
- 同键同哈希返回原批次、方案和版本；同键不同哈希返回 HTTP 409。
- 一个批次内所有 SKU 和版本必须事务化保存，不能只保存部分 SKU。
- 成功响应返回批次 ID、每个方案 ID、版本 ID、版本号和商品利润表行的稳定 ID。
- 记录完整的输入、有效返点、规则版本和结果，避免未来规则更新后历史结果被重新解释。

### 9.6 权限与归档

- 查看共享商品利润表要求 `profit_record_view`；创建、修改元数据和新增版本要求 `profit_record_edit`。
- 创建人可编辑自己创建的方案名称、备注等元数据并新增版本；任何计算输入或结果变化都必须创建新版本，历史版本接口不提供 PATCH/DELETE。
- 管理员/主账号可编辑和归档全部方案。
- 已保存历史版本默认不可物理删除；普通操作只归档。
- 整个方案未被其他业务记录引用时，主账号可以永久删除该方案及其版本；必须二次确认、清楚列出影响并写审计日志。被其他业务记录引用时只能归档。

## 10. 数据库迁移与生产数据

### 10.1 预期迁移

本次预计需要 schema migration，至少覆盖：

- 调拨完成异常状态、`closed_at`、`closed_by` 或等价结束审计字段，以及唯一结束请求/事件记录；
- 调拨行数量约束：`received_quantity >= 0`、`exception_closed_quantity >= 0`、`received_quantity + exception_closed_quantity <= quantity`；
- 达人档案、合作、寄样/物流、内容、跟进及归因记录；
- 利润试算批次、方案、不可变版本、请求哈希和幂等唯一约束；
- 新能力目录、权限回填、归档字段和必要审计字段。

广告返点若保存在现有 JSON config 中可不新增 working-config 表字段，但 serializer 必须显式校验并保证旧配置默认值为 0。

### 10.2 数据安全

- migration 不得猜测旧达人、旧 GMV 或旧利润记录。
- 新字段应使用兼容默认值或允许空值，先迁移结构再由用户录入。
- 调拨历史数据不得批量自动结束。
- 添加调拨数量约束前，先用只读检查列出所有违规行；存在脏数据时阻止正式 migration，先备份并按单据审计修复，不能让生产迁移中途失败。
- 权限回填默认仅让主账号/管理员获得全部新能力，其他成员保持最小权限；提供 dry-run 列出每个受影响账号和将新增的能力，代码回滚后未知能力值必须可安全保留。
- 部署前备份 PostgreSQL；记录备份路径和部署前精确 SHA。
- migration 必须在包含生产结构与代表性数据的副本上完成正向和反向演练；正式反向迁移前单独导出新表并记录各表行数。

### 10.3 回滚

- 代码回滚到部署前精确 SHA。
- 新 migration 的逆向回滚会删除新表及部署后录入的数据，执行前必须再次备份并明确确认。
- 如果新功能已经产生业务数据，优先回滚代码并保留数据库结构；不得未经确认直接反向迁移丢数据。
- 单条调拨异常关闭属于真实业务动作，代码回滚不会自动恢复来源仓库存；如操作错误必须走审计后的库存纠错流程，不能直接改余额字段。

## 11. 必须新增的回归测试

### 11.1 调拨结束

- 部分收货后结束全部剩余，状态为 `completed_with_exception`。
- 每个 SKU 剩余量全部进入 `exception_closed_quantity`。
- 目的仓在途归零，不增加 `on_hand`，来源仓不恢复。
- 多 SKU 原子处理；任一行失败全部回滚。
- 同键同请求返回原结果；同键不同内容和不同键操作终态均返回 409。
- 收货与结束调拨并发不会超收、重复关闭或造成余额/明细失配。
- 数据库数量约束及 migration 前脏数据检查。
- 前端点击、原因、二次确认、API 一次、刷新状态和库存。

### 11.2 智能补货表头

- 页面纵向滚动后表头固定在顶部导航下。
- 横向滚动同步；固定表头与数据单元格左右边界误差不超过 2 px，商品图片/名称/SKU 的外接矩形位于“商品”列内。
- 切换模块后固定表头消失。
- 至少使用 1440×900 桌面视口完成真实 DOM/浏览器测试，并接入仓库可重复运行的测试命令；不只检查字符串或人工截图。

### 11.3 各仓近 7 天出库

- 多仓订单出库、手动出库和退货分别计算。
- 调拨、调整和已撤回流水排除。
- 退货按原销售日与原仓库冲减。
- 各仓 `Warehouse.timezone` 下 `[今天-6 天 00:00, 明天 00:00)` 起止和午夜边界正确，日均固定除以 7。
- 接口权限隐藏无权仓库。
- 前端移除“查看补货参数”，周期明细正确显示每仓和合计。

### 11.4 数据分析

- 日期、店铺、仓库和 SKU 筛选。
- 订单/件数/出库/缺货/取消/退货聚合正确。
- `ordered_at`、`shipped_at`、取消时间、退货发生时间和销售期退货冲减分别按定义归属，自定义结束日包含整天。
- 无真实金额时不生成 GMV 或利润。
- 商品利润表试算结果不冒充经营分析实际利润。
- 店铺名无法唯一匹配时进入“未关联店铺”。
- 旧竞品路由和既有竞品数据保持可用。
- 无 `analytics_view` 的成员访问 GET 接口也返回 403；有权限成员只能聚合授权仓库，但可查看本组织全部店铺。

### 11.5 广告返点与配置持久化

- 返点 0%、10%、100% 边界。
- ROI、CPA USD、广告占比三种输入均按实际广告成本重算。
- `USD_PER_MYR` 方向、每 SKU 舍入和多 SKU 汇总正确。
- SKU 返点 `null` 继承全局，显式 `0` 覆盖为零返点。
- 非 CPA 模式不生成真实 CPA；未填写广告数据不生成真实 ROI。
- 全局返点与 SKU 覆盖优先级。
- working config 防抖保存、F5 恢复、同组织共享。
- 两个独立登录会话并发修改 working config 时触发乐观锁冲突，不静默后写覆盖；初次加载不会自动保存默认值。
- SKU 临时输入不被 working config 自动保存。
- 任一配置接口失败时其他成功数据仍展示，并显示准确错误。

### 11.6 达人管家

- 只有昵称也可保存，其他字段留空。
- 组织隔离、权限、归档和永久删除限制。
- 已被业务记录引用的达人即使主账号也不能永久删除。
- 无 `creator_view` 时列表、详情、联系方式、备注和导出均不可读取；审计日志不复制完整敏感值。
- 合作、寄样、内容、跟进流程。
- 手工/授权归因来源；不自动推断归因。

### 11.7 商品利润表

- 多 SKU 计算一次保存为同一批次、多条 SKU 行。
- 主表显示各方案最新版本。
- 查看原结果不重算；按当前规则重算生成新版本并显示规则差异，旧版本不变。
- 另存为方案生成独立方案。
- 篡改浏览器提交的净利润/ROI 不会进入数据库，保存以服务端重算结果为准。
- 同键同哈希返回原结果，同键不同哈希返回 409；并发保存不产生重复版本号。
- 刷新和其他组织成员查看后数据仍存在。
- 无 `profit_record_view` 的成员访问列表和详情 GET 接口也返回 403。
- 归档、权限和审计日志正确。
