## 3. 主页面最终结构

### 3.1 策略栏

策略栏放在`计算配置`面板顶部、具体配置字段之前，保持一整行：

```text
[西马标准] [东马配置] [BXP 活动] [+ 新建计算策略] [保存当前策略] [删除策略]
```

要求：

1. 已保存策略直接显示用户自定义名称，不显示“策略1/策略2”。
2. 当前默认策略使用清楚但不过重的选中样式。
3. 策略较多时，策略名称区域横向滚动；操作按钮不能被挤成多行或消失。
4. `保存当前策略`和`删除策略`仅在已有当前策略时可用；没有策略时隐藏或禁用。
5. 不再显示：
   - `计算策略`下拉框；
   - 主页面`策略名称`输入框；
   - 主页面`买家收货地区`下拉框；
   - `保存为默认策略`旧按钮及旧说明。

建议 DOM 标识：

- `profitStrategyBar`
- `profitStrategyList`
- `profitStrategyCreate`
- `profitStrategySaveCurrent`
- `profitStrategyDelete`
- 策略项使用`data-profit-strategy-id`。

### 3.2 计算配置字段

删除配置面板中的`计算币种`下拉框，但保留页面右上角 MYR/CNY 结果显示切换。

桌面端建议排列：

第一行：

1. 销售国家
2. 发货方式
3. 店铺身份
4. 类目佣金调整
5. 交易手续费调整

第二行：

1. 是否参加 BXP
2. 买家是否支付运费

其中 BXP 与买家支付运费必须在同一视觉行。其余空间保持干净，不用为了填满列数增加空配置。

主页面不显示买家收货地区。地区由当前策略保存并在计算请求中使用。

## 4. 策略数据范围

每套策略保存：

- 销售国家；
- 发货方式；
- 店铺身份；
- 类目佣金调整；
- 交易手续费调整；
- 是否参加 BXP；
- 买家是否支付运费；
- 买家收货地区；
- 页面显示币种偏好可继续沿用现有配置字段。

不保存：

- SKU 行；
- 产品成本、售价和重量；
- 达人佣金逐 SKU 手动覆盖；
- 广告输入；
- 每日汇率数值；
- 当前计算结果。

## 5. 新建策略

点击`＋ 新建计算策略`打开自定义模态框，不使用浏览器原生`prompt`。

弹窗只包含：

1. 策略名称；
2. 买家收货地区。

其余字段不在弹窗重复填写。保存时直接读取主页面当前配置，并与弹窗字段合并后保存。

地区规则：

- 默认选择`西马`；
- 不继承当前策略的地区；
- 当主页面`买家是否支付运费`关闭时，地区控件保留但置灰；
- 置灰时显示：`关闭买家支付运费时，收货地区不参与计算`；
- 后台仍保存`west_malaysia`，重新开启运费开关后可直接使用。

保存成功后：

- 新策略成为当前策略；
- 立即成为组织默认策略；
- 顶部显示其自定义名称；
- 下次进入利润试算自动加载。

## 6. 点击和切换策略

点击任意策略名称时必须：

1. 直接放弃主页面当前未保存的临时修改，不弹提示；
2. 从服务器读取并回填该策略全部配置；
3. 立即在服务器端将该策略设为组织默认策略；
4. 更新标签选中状态；
5. 下次打开页面自动加载最后点击的策略。

仅前端切换样式不算完成，默认状态必须持久化到数据库。

建议新增：

```http
POST /api/profit-calculator/strategies/{id}/activate/
```

响应返回更新后的策略。动作必须使用数据库事务和行锁，保证同组织只有一个默认策略。

## 7. 保存当前策略

点击`保存当前策略`，打开操作弹窗：

- `覆盖当前策略`
- `另存为新策略`
- `取消`

### 7.1 覆盖当前策略

继续打开编辑弹窗：

- 策略名称只读，保持不变；
- 买家收货地区可修改；
- 买家运费关闭时地区置灰并保存西马；
- 保存时使用主页面当前配置覆盖当前策略；
- 保存成功后保持当前并设为默认。

### 7.2 另存为新策略

打开与新建相同的弹窗：

- 填写新策略名称；
- 选择买家收货地区；
- 读取主页面当前其他配置一起保存。

## 8. 同名策略覆盖规则

用户已确认：新建或另存时输入同组织已有名称，不报重名错误，直接覆盖该同名策略。

后端要求：

1. 保留数据库`(organization, name)`唯一约束，防止并发产生重复行；
2. API 在事务中按`organization + name`查找；
3. 找到同名策略时更新其 config、updated_by、updated_at，并设为默认；
4. 同组织其他策略取消默认；
5. 前端切换到被覆盖的策略；
6. 新建返回 201；同名覆盖可返回 200；
7. 不能用捕获 409 后再无事务重试的方式模拟覆盖；必须保证并发一致性；
8. 更新当前策略时，若名称不变，按当前 ID 覆盖。

当前测试`test_strategy_name_is_unique_inside_an_organization`中“第二次同名创建返回 409”的断言必须替换为覆盖成功断言。

## 9. 删除策略

增加`删除策略`按钮，只作用于当前选中策略。

点击后弹出二次确认：

```text
确定删除策略“西马标准配置”吗？
删除后无法恢复。

[确认删除] [取消]
```

确认后：

1. 后端删除当前组织内该策略；
2. 还有其他策略时：选择当前列表中的第一项，立即设为默认并回填；
3. 没有剩余策略时：恢复系统默认配置，顶部只显示`＋ 新建计算策略`；
4. 删除只影响策略，不影响 SKU、广告输入、汇率和业务数据；
5. 写入审计日志。

后端 ViewSet 必须允许 DELETE，且必须验证组织范围。

建议列表稳定顺序：默认策略优先，其余按`name, id`；删除默认后按`name, id`取第一项作为新的默认。

## 10. 无策略时

当组织内没有任何策略：

- 不自动创建数据库“默认策略”；
- 主页面使用系统默认配置；
- 顶部只显示`＋ 新建计算策略`；
- `保存当前策略`和`删除策略`不可用；
- 第一次新建保存成功后才出现自定义名称，并设为默认。

系统默认值沿用现有规则配置，不扩大本需求范围。

## 11. 币种显示恢复

右上角 MYR/CNY 切换保留，并控制主币种。

禁止继续通过重复定义`formatMoney`把全页面强制改成双币。建议拆分：

```js
formatSingleMoney(value, currency)
formatDualMoney(value, primaryCurrency)
formatSecondaryMoney(value, secondaryCurrency) // 带“≈”由调用处决定
```

### 11.1 顶部利润卡

MYR 为主：

```text
RM 20.69
≈ ¥ 34.13
```

CNY 为主：

```text
¥ 34.13
≈ RM 20.69
```

- 第一行大字、加粗；
- 第二行小字、弱化；
- 不清空`profitNetCny`；
- 第一行不能出现双币斜杠。

### 11.2 左侧费用明细

金额列只显示当前主币种：

- MYR：`RM 3.78`
- CNY：`¥ 6.35`

不显示辅助币种，不显示`／`，表头继续显示`金额(MYR)`或`金额(CNY)`。

### 11.3 右侧金额明细

继续保留同行双币：

- MYR 主：`RM 20.69 ／ ¥ 34.13`
- CNY 主：`¥ 34.13 ／ RM 20.69`

右侧现有九项及后端金额口径不在本需求中改变。

## 12. 费用分组箭头和折叠

### 12.1 保留现有分组条件

- 只有 1 个费用项：单行显示，无合计、无箭头、无折叠；
- 2 个及以上：显示分组合计和明细。

不得破坏`group.items.length === 1`现有逻辑。

### 12.2 默认折叠

所有多项分组：

- 初始`aria-expanded="false"`；
- 明细行初始 hidden；
- 每次点击`计算利润`获得并渲染新结果时，全部重新恢复折叠；
- 不保留上一次计算前的展开状态。

### 12.3 SVG 箭头

删除字体字符`⌄`和`›`，改用同一个内联 SVG：

- 折叠：箭头向右；
- 展开：通过 CSS transform 旋转向下；
- 建议可视尺寸 18–20px；
- 使用较粗圆角线条，建议`stroke-width`约 2.2；
- 固定图标容器宽度，避免组名起始位置跳动；
- SVG 与“平台费用、达人费用、物流”等文字垂直居中；
- 图标和文字间距统一。

交互：

- 点击 SVG、组名或整条汇总行都可展开/折叠；
- Enter/Space 可操作；
- 点击规则链接、编辑按钮等内部交互控件时不得触发折叠；
- 更新行和按钮上的`aria-expanded`。
