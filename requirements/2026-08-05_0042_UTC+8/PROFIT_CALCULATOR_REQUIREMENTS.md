## 3. 业务口径总原则

1. 本页面是利润预测工具，不接收、同步或优先使用真实结算手续费。
2. 真实结算单只用于验证公式和四舍五入结果。
3. MYR 是后端计算本位币；CNY 仅用于展示和人民币采购成本换算；USD 仅用于以 USD 定义的 CPA 指标。
4. 所有核心公式必须在后端统一计算；前端只负责提交参数、展示结果和币种换算顺序，不复制第二套利润公式。
5. 金额统一使用 Decimal，并按每个费用规则要求在 MYR 分位四舍五入；不得用二进制浮点作为最终财务结果。

## 4. 买家运费与交易手续费

### 4.1 计算配置字段

在“计算配置”增加：

- `买家是否支付运费`：开关，默认关闭或由默认策略决定。
- `买家配送区域`：`西马`、`东马`；开关开启时可用，默认 `西马`。
- 当前渠道：`Standard`。第一版可作为版本化规则中的固定渠道，不要求用户额外选择；代码结构必须允许未来新增渠道。
- `官方交易手续费率`：只读，当前规则值 3.78%。
- `交易手续费率调整`：可正可负，单位为百分点，默认 0.00。
- `调整后交易手续费率`：只读结果。

命名必须使用“交易手续费率调整”，不要使用“实际使用费率”。

### 4.2 买家支付运费规则

当前已确认的 Malaysia Standard 规则：

| 区域 | 买家支付运费 |
|---|---:|
| 西马 | RM2.90 |
| 东马 | RM8.00 |

- 关闭“买家是否支付运费”时，买家支付运费为 RM0.00。
- 开启时按当前版本化价表、渠道和区域自动取值，不在费用明细内手工输入。
- 默认区域为西马。
- 该金额是一次测算/一笔订单级金额，只加入一次，不能按 SKU 行数重复乘算。
- 本轮自动规则只覆盖已核验的跨境 Standard 场景；选择本土发货时不得套用这份跨境价表，可将该开关禁用并返回 RM0，直到另有本土运费规则。

### 4.3 跨境段物流与净物流成本

跨境段物流成本继续按价表计算：

```text
跨境段物流成本 = ceil(包装后重量 ÷ 10g) × RM0.15
```

真实结算逻辑可表示为：

```text
平台显示的实际运费 = 跨境段物流成本 + 买家支付运费
净物流成本 = 平台显示的实际运费 - 买家支付运费
```

因此预测结果中的净物流成本等于商家实际承担的跨境段物流成本。左侧费用明细不要新增重复的右侧汇总项目；可以保留现有物流项目，但必须做到：

- `商家运费（系统估算）`或更准确的`净物流成本（系统估算）`展示净物流成本；
- `买家支付运费（系统预测）`可作为参考项展示，不能再提供手工编辑；
- 物流分组总额必须等于净物流成本；
- 计费基准说明中可以展示“平台实际运费、买家支付运费、净物流成本”的关系，但不要新增多余独立列。

### 4.4 交易手续费公式

```text
调整后交易手续费率
= max(0, 官方交易手续费率 + 交易手续费率调整)
```

```text
交易手续费计费基数
= 商品销售收入合计
+ 买家支付运费
- 与交易手续费相关的客户退款
```

关闭买家运费开关时，买家支付运费为 0。

```text
预测交易手续费
= 交易手续费计费基数 × 调整后交易手续费率
```

示例：

```text
商品售价 RM16.99
西马买家支付运费 RM2.90
官方交易手续费率 3.78%
调整 0.00 个百分点

计费基数 = RM19.89
手续费 = RM19.89 × 3.78% = RM0.75
```

### 4.5 费率调整边界

- `+0.20` 表示增加 0.20 个百分点：3.78% → 3.98%。
- `-0.20` 表示减少 0.20 个百分点：3.78% → 3.58%。
- 不是乘法调整。
- 调整后费率不得小于 0%。
- API 返回官方费率、调整百分点和最终费率，费用明细可审计。

## 5. 计算策略保存

### 5.1 作用范围

- 策略按组织保存，共享给该组织的利润测算页面。
- 不按店铺分别保存。
- 可保存多套策略，每套策略有用户自定义名称。
- 同一组织内策略名称唯一，建议使用去首尾空格后的精确名称判重。

### 5.2 保存内容

策略保存“计算配置”而不是商品试算数据，至少包括：

- 销售国家；
- 发货方式；
- 店铺身份；
- BXP 开关；
- 类目佣金调整百分点；
- 买家是否支付运费；
- 买家配送区域；
- 交易手续费率调整百分点；
- 页面主显示币种（MYR/CNY，可作为界面偏好保存）。

不保存：

- SKU 行、商品售价、商品成本、重量、达人佣金、广告数据；
- 每日自动汇率的具体数值和快照；
- 真实结算数据。

### 5.3 默认策略

- 新建、覆盖或另存成功后，该策略立即成为默认策略。
- 同一组织只能有一个默认策略。
- 下次进入利润测算自动加载默认策略。
- 页面临时修改但未保存，不覆盖数据库中的策略。

### 5.4 保存交互

- 计算配置区增加策略选择器、策略名称和“保存”按钮。
- 未加载现有策略时点击保存：填写唯一名称并创建。
- 已加载策略且配置发生变化时点击保存，弹窗提供：
  - `覆盖当前策略`
  - `另存为新策略`
- 另存为新策略时必须输入新的唯一名称。
- 本轮不要求删除、重命名或历史版本管理，不要额外扩大范围。

### 5.5 建议数据模型

新增组织级模型，例如：

```text
ProfitCalculationStrategy
- id
- organization_id
- name
- config JSONField
- is_default
- created_by
- updated_by
- created_at
- updated_at
```

约束：

- `(organization, name)` 唯一；
- 每个 organization 最多一个 `is_default = true`；
- 设置默认、覆盖配置和取消旧默认必须在同一数据库事务内完成。

### 5.6 建议 API

```text
GET   /api/profit-calculator/strategies/
POST  /api/profit-calculator/strategies/
PATCH /api/profit-calculator/strategies/{id}/
```

- `GET` 返回策略列表和默认标记。
- `POST` 创建新策略并将其设为默认。
- `PATCH` 用于覆盖当前策略，同时设为默认。
- 重名返回 409 或明确的字段校验错误，不静默覆盖。

## 6. LVG 商品税

### 6.1 最终规则

- 跨境发货且单件商品售价 `<= RM500.00`：售价视为已含 LVG 10%，税额按含税拆分。
- 本土发货：LVG = RM0.00。
- 单件商品售价 `> RM500.00`：不自动使用 LVG 10%，状态显示“超出 LVG 范围”，不猜测进口关税或其他税费。

```text
LVG 税额 = 含税售价 × 10 / 110
```

边界测试必须包含 RM500.00 和 RM500.01。

### 6.2 成本和结算口径

本轮以真实 TikTok 结算单的 SST/LVG 扣费结构为准：

- LVG 税不重复加到商品收入；
- LVG 税进入平台结算费用、总费用、广告前总成本和广告后总成本；
- 达人佣金的计费基准继续使用`含税售价 - 自动拆出的 LVG 税额`；
- 左侧费用明细保留 LVG 行和规则来源。

现有“仅展示、不重复扣作卖家成本”的实现和说明必须同步修改，避免前端、规则页、测试互相矛盾。

## 7. 金额和利润公式

### 7.1 总收入

```text
总收入 = 商品销售收入合计
```

买家支付运费不计入总收入。

### 7.2 总费用

```text
总费用
= 平台类目佣金
+ 交易手续费
+ BXP / 其他平台服务费
+ 平台支持费
+ 达人推广佣金
+ LVG 商品税
+ 净物流成本
+ 其他平台结算费用
```

总费用不包含商品采购成本和广告费。

### 7.3 总结算金额

```text
总结算金额 = 总收入 - 总费用
```

### 7.4 广告前总成本与毛利

```text
广告前总成本合计
= 总费用
+ 商品采购成本
+ 其他非广告经营成本
```

```text
广告前毛利 = 总收入 - 广告前总成本合计
毛利率 = 广告前毛利 ÷ 商品销售收入合计
```

### 7.5 广告后总成本与净利润

```text
广告后总成本合计 = 广告前总成本合计 + 广告费用
净利润 = 总收入 - 广告后总成本合计
利润率 = 净利润 ÷ 商品销售收入合计
```

没有填写有效广告数据时：

- 广告前总成本、广告前毛利、毛利率正常计算；
- 广告后总成本、净利润、利润率显示“未计算”，不能显示 0 造成误解。

## 14. 前端实现约束

1. 双币格式必须由一个公共格式化函数生成，例如 `formatDualMoney(myrAmount, primaryCurrency)`；不允许每个卡片各写一套。
2. 费用分组金额、顶部指标和右侧卡片必须使用同一格式化函数。
3. 策略加载后只填写配置控件，不覆盖当前 SKU 行。
4. 买家运费开关关闭时禁用区域选择，并明确显示 RM0.00。
5. 买家运费开关开启时显示当前规则版本和预测金额，不提供手工金额输入。
6. 交易手续费调整改变后，重新计算必须即时反映在计费基准、费率和金额中。
7. 右侧金额卡片不在前端重新推导总费用或利润，直接使用后端汇总字段。

## 15. 数据迁移与兼容

- 新增策略模型需要 Django migration。
- 旧的 `buyer_shipping_fee` 请求字段可以短期兼容读取，但页面不再发送；最终计算必须以配置开关和区域规则为准，避免手工值绕过规则。
- 为防止旧浏览器缓存，本次发布需要更新静态资源版本参数。
- 规则版本需要升级，运费规则版本应同时包含跨境段和买家支付运费的版本信息。
- 规则与说明页面必须同步更新，不得继续写“买家运费默认 0，可在费用明细手动编辑”或“LVG 仅展示不计成本”。
