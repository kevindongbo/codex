# 四十二、调拨异常关闭测试

必须覆盖：

发出 100：

来源仓减少 100。

目标仓：

在途 100。

收到 80：

目标仓增加 80。

剩余在途 20。

异常关闭 20：

- 目标仓不增加库存；
- 来源仓不恢复库存；
- 在途归零；
- exception_closed = 20；
- 原因保存；
- 调拨完成；
- 使用同一 idempotency_key 重试不得重复处理。

同时增加前端测试：

确认 `closeTransferException()` 请求 body 一定包含：

`idempotency_key`

# 四十三、验收标准

全部满足以下条件才视为完成：

1. 调拨异常关闭不再报 `idempotency_key` 必填。
2. 重复点击异常关闭不会产生重复库存流水。
3. 全仓加权日均使用所有仓库真实出库。
4. 订单出库 + 手动出库计入。
5. 退货不扣需求。
6. 报损不计需求。
7. 3/7/15/30 权重公式严格使用加权总量 / 加权天数。
8. 权重总和必须 100%。
9. 支持全局权重 + SKU 权重覆盖。
10. SKU 权重支持恢复全局。
11. 主力仓支持单个、批量、全选设置。
12. 有主力仓时 SKU 只在对应主力仓补货页显示。
13. 无主力仓时不给正式补货决策。
14. 库存只使用主力仓。
15. 其他仓库存不抵扣。
16. 可售天数不包含在途。
17. 建议补货库存位包含已确认在途。
18. 目标覆盖默认 30，可修改，可清空。
19. 有覆盖天数时不叠加安全库存。
20. 无覆盖天数时使用固定安全库存模式。
21. 目标覆盖只决定补到多少，不决定提前多久触发。
22. 安全库存模式的安全库存参与触发点。
23. 未到触发点建议补货必须为 0。
24. 起订量允许为空。
25. 整箱数允许为空。
26. UI 不使用 MOQ 文案。
27. 预测到货周期恢复历史 P80 优先。
28. 最迟下单不再减额外安全天数。
29. 删除用户可编辑检查频率。
30. 后台每日自动检查。
31. 关键业务变化后实时重算。
32. 选择框列缩窄。
33. 商品列向左。
34. 标题改成“全仓加权日均出库”。
35. 近30日出库来源主表只显示总数。
36. 周期和仓库明细使用 Popover / Modal，不撑高表格行。
37. 所有新公式有后端单元测试。
38. 前后端接口字段和计算结果保持一致。

# 四十四、开发原则

这不是新建智能补货模块，而是**修正现有模块**。

Codex 开发时必须：

1. 优先复用现有采购、库存、StockLedger、调拨、补货推荐结构；
2. 保留历史数据；
3. 用 migration 完成字段调整；
4. 不直接破坏旧 recommendation snapshot；
5. 旧历史推荐仍然可查看；
6. 新 recommendation 使用新的 calculation version，例如：
   `v3_all_warehouse_primary_warehouse`
7. 后端是最终计算真值；
8. 前端不得再维护另一套与后端不一致的补货公式；
9. 本地 fallback 计算如保留，也必须复用完全相同公式或明确只用于开发模式；
10. 修改完成后运行 ERP 相关后端测试、前端测试，并重点验证采购、调拨和库存流水没有回归。
