# 4. 利润试算页面

## 4.1 计算配置区域

所有配置项需要统一：

- 标题基线
- 输入框和选择框高度
- 上下间距
- 列宽与对齐
- 响应式换行

不得因某一项说明过长而把整行撑高。

“类目佣金调试”显示为：

> **类目佣金调试（按百分点临时调整）**

要求：

- 主标题使用正常字号和字重。
- 括号内备注字号更小、颜色更浅，紧跟在主标题后。
- 删除输入框下方原有长说明。
- 其他计算配置标题不增加类似备注。
- 默认值 `0.00`。
- 计算公式：`实际类目佣金率 = 官方类目佣金率 + 调试百分点`。
- 可填正数或负数。
- 仅当前试算临时生效，不保存到 SKU；重新进入试算时恢复 `0.00`。

## 4.2 删除黄色说明框

利润计算页面中的黄色说明框全部删除，不保留短提示，包括运费、买家运费、LVG、佣金、补贴、活动、广告等说明。

所有规则迁移到“规则与说明”页面。计算页面只保留：

- 输入项
- 计算结果
- 必要的错误提示
- 加载和保存状态

## 4.3 费用明细名称与顺序

最终顺序：

1. 商品售价
2. 平台代扣合计
3. 商品采购成本
4. 达人佣金
5. 税费
6. 物流费用
7. 广告费用

要求：

- 不再使用“收入”“商品”“推广代扣”等抽象分类名称。
- 不出现“收入合计”“商品合计”“推广代扣合计”。
- 金额为 `RM0.00` 的项目也必须显示，不隐藏。
- 除“平台代扣合计”外，其他项目均为直接单行展示。

## 4.4 平台代扣合计

- 类目佣金
- BXP 服务费
- 支付交易手续费
- 平台支持费
- 其他实际平台扣费（存在时）

要求：

- 主行在展开后仍显示总金额。
- 明细底部不再重复增加“小计”或“合计”行。
- 明细之和必须等于主行总金额。
- 点击子项、复制金额或选择文本时不得误触收起。
- 展开区使用缩进、浅背景和留白，不使用密集重横线。
- 支持键盘 Enter/Space，并维护 `aria-expanded`。

# 5. TikTok Shop 马来西亚费用规则

规则最后核验时间：2026-08-03（北京时间）。官方规则可能变化，规则引擎必须版本化，不能永久硬编码。

## 5.1 支付交易手续费

从 2026-02-15 00:00（马来西亚时间，GMT+8）起：

```text
支付交易手续费 =
(商品原价 - 商家折扣 + 买家支付运费 - 顾客订单退款金额) × 3.78%
```

要求：

- 3.78% 包含 SST。
- 不设置 RM4.13 封顶。
- 平台优惠不从计费基数中扣除。
- 买家支付运费进入交易手续费基数，但不计入商品销售收入。
- 部分退款按官方退款后基数重算。
- 本土和跨境卖家均适用。

官方来源：

- https://seller-my.tiktok.com/university/essay?knowledge_id=10013511&lang=en

## 5.2 平台支持费

默认有效规则：

- 每个成功送达订单 RM0.54（含 SST）。
- 按订单收取，不按件数收取。
- 成功送达后，即使后续退货或退款，默认不退还；仍需按当时官方规则版本处理。
- 规则需要支持官方豁免政策。

多 SKU 分摊：

- 按各 SKU 折后销售金额占比分摊。
- 单 SKU 承担全部费用。
- 尾差分配给折后金额最高的 SKU。
- 分摊总和必须严格等于订单支持费。

官方来源：

- https://seller-my.tiktok.com/university/essay?knowledge_id=7992113007347457&lang=en

## 5.3 类目佣金与 BXP

类目佣金计费基数：

```text
类目佣金 = (商品原价 - 商家折扣) × 有效类目佣金率
```

运费和 TikTok 平台优惠不进入类目佣金基数。

费率必须根据以下维度读取有效版本：

- 国家/地区
- Marketplace 或 Mall
- BXP 或非 BXP
- 最终商品子类目
- 试算日期或订单日期
- 生效版本

BXP 作为独立平台代扣明细，不与类目佣金合并展示。当前官方资料示例中的 BXP 费率为 4.86%（含 SST），但必须从有效规则版本读取。

官方来源：

- https://seller-my.tiktok.com/university/essay?knowledge_id=6907739532281602&lang=en

# 6. 规则与说明页面

## 6.1 页面结构

按以下逻辑组织，不得简单堆叠原黄色文字：

1. 计算口径概览
2. 平台费用规则
3. 商品与推广费用
4. 税费规则
5. 物流费用规则
6. 汇率规则
7. 退款与特殊订单
8. 来源与版本

每条规则尽量展示：

- 规则名称
- 适用范围
- 计算公式
- 示例
- 当前系统参数
- 数据来源
- 生效日期
- 最近核验时间
- 规则版本

## 6.2 权限

- 所有已登录账号可查看。
- 只有主账号持有者可以编辑、定时生效、取消计划、回滚。
- 普通管理员、经理、采购、仓库和其他子账号不可修改。
- 后端必须执行权限校验，不能只隐藏前端按钮。

## 6.3 修改与二次确认

主账号修改规则时：

1. 进入编辑状态。
2. 修改费率、固定费用、生效日期、公式或说明。
3. “修改原因”必填。
4. 选择立即生效或定时生效。
5. 点击保存后弹出二次确认。
6. 弹窗显示规则名称、原值、新值、生效时间、影响范围、修改原因。
7. 二次确认后才保存。

## 6.4 生效方式

- 立即生效。
- 定时生效：按北京时间（UTC+8）所选日期的 00:00 生效。
- 必须由服务端统一调度，不依赖浏览器时区。
- 生效前可以取消或修改，但仍需填写原因并二次确认。
- 利润试算按试算日期读取当时有效规则版本。

## 6.5 历史与回滚

- 每次修改生成新版本，不覆盖或删除旧版本。
- 记录操作人、时间、原因、原值、新值、生效日期。
- 主账号可以选择任意历史版本回滚。
- 回滚原因必填，并需要二次确认。
- 回滚生成新版本，并记录来源历史版本号。

# 7. 汇率功能

## 7.1 范围与口径

币种：CNY、MYR、USD。

支持六个方向：

- CNY → MYR
- MYR → CNY
- USD → MYR
- MYR → USD
- CNY → USD
- USD → CNY

使用市场中间价。后端只保存一组一致的基准关系，再推导反向和交叉汇率，避免六个方向相互矛盾。

## 7.2 自动更新

- 使用系统已配置且具备联网搜索能力的 DeepSeek。
- 每天北京时间 09:00 自动更新。
- 必须由后端调用，不得暴露模型密钥到浏览器。
- DeepSeek 必须联网查找可靠来源，不能使用模型记忆猜测。
- 返回结构化数据：币种、汇率、查询时间、来源。
- 服务端验证：正数、倒数关系、交叉汇率一致性、异常波动。
- 查询失败或数据异常时，保留上一条有效值并显示失败状态。

## 7.3 手动刷新与修正

手动刷新：

- 所有已登录账号均可操作。
- 立即调用 DeepSeek 联网查询。
- 显示加载状态，防止重复点击。

手动修正：

- 仅主账号持有者可操作。
- 不需要填写原因，也不需要二次确认。
- 保存后立即生效，仅当天有效。
- 次日 09:00 自动更新成功后覆盖手动值。
- 自动更新失败时继续沿用上一有效值。
- 后台保留日志，但前台不提供汇率历史入口。

# 9. 仓间调拨

## 9.1 状态与筛选

状态：

1. 草稿
2. 调拨在途
3. 部分调入
4. 已调入
5. 已取消

筛选：

- 进行中：调拨在途、部分调入；不包含草稿。
- 已经结束：已调入、已取消。
- 全部：全部状态，包括草稿。
- 默认进入“进行中”。

## 9.2 草稿

- 仅在“全部”中显示。
- 可编辑商品、数量和调入仓。
- 可新增/删除商品行。
- 可直接删除。
- 草稿不扣调出仓库存，不增加在途库存，删除不生成库存流水。

## 9.3 调出仓与调入仓

调出仓：

- 正式发出后固定，不允许修改。

调入仓：

- 草稿和进行中均可修改，无需重新建单。
- 修改进行中的调入仓时，只转移剩余在途数量。
- 调出仓已经扣减的库存保持不变。
- 已收货库存继续留在原调入仓。
- 保留原调拨单编号。
- 记录修改前后仓库、操作人和时间。
- 新调入仓必须启用、可收货，且不能等于调出仓。

## 9.4 进行中二次编辑

调拨在途允许：

- 调整原有数量。
- 新增商品行。
- 删除商品行。
- 修改调入仓。

库存规则：

- 新增商品或增加数量：校验调出仓可用库存，扣减新增差额并增加在途。
- 删除商品或减少数量：减少在途并把差额退回调出仓。
- 任一 SKU 库存不足时整次操作回滚，不允许部分成功。
- 所有变化生成库存流水和操作记录。

## 9.5 部分调入

支持按 SKU、分多次收货：

- 每次填写本次实收数量。
- 不得超过剩余在途数量。
- 实收增加调入仓库存。
- 未收数量继续在途。
- 仍有未收数量时状态为“部分调入”。
- 全部收完后状态为“已调入”。
- 每次收货生成独立收货记录与库存流水。

## 9.6 部分调入后的编辑

- 已收货商品与数量锁定，普通编辑不可修改。
- 只允许编辑剩余在途部分。
- 剩余部分可以新增、删除、增加或减少数量。
- 修改调入仓时只转移剩余在途数量。
- 若要修改已收货数量，必须先撤回对应收货记录。

## 9.7 撤回收货

每次收货记录均可单独撤回：

- 调入仓扣减本次收货数量。
- 对应数量恢复在途。
- 状态重新计算为调拨在途或部分调入。
- 原收货记录保留，新建“收货撤回”记录。
- 生成库存冲销流水。
- 记录操作人、时间和撤回原因。

撤回前必须检查调入仓当前可用库存。库存不足时禁止撤回，不得产生负库存，并提示先补回库存或减少撤回数量。

## 9.8 删除与取消

- 草稿：可直接删除。
- 调拨在途：不能物理删除，只能取消；剩余在途退回调出仓并保留记录。
- 部分调入：可取消剩余在途；已收货部分保持。整单取消前必须撤回全部收货。
- 已调入：不能直接删除或取消；先撤回全部收货，再取消。
- 所有取消、撤回和库存退回均生成库存流水。

# 10. 智能补货

## 10.1 默认权重

- 最近 3 天：40%
- 最近 7 天：30%
- 最近 15 天：20%
- 最近 30 天：10%

合计必须为 100%，否则禁止保存。

## 10.2 全局修改

“全局修改”只覆盖当前仓库的全部有效 SKU：

- 覆盖此前的单独权重并清除旧覆盖配置。
- 不影响其他仓库。
- 自动重算受影响 SKU。
- 保存前必须二次确认。

确认弹窗显示：

- 当前仓库名称
- 受影响 SKU 数量
- 原权重
- 新权重
- 原有单独权重将被覆盖

## 10.3 部分 SKU 修改

- 可勾选一个或多个 SKU。
- 为所选 SKU 批量设置同一组权重。
- 只影响所选 SKU。
- 保存后自动重算。

## 10.4 全选

- 全选必须选择当前仓库全部有效 SKU。
- 不受筛选、分页和当前渲染行影响。
- 取消全选清空当前仓库全部选择。
- 显示“已选 X 个 SKU”。

## 10.5 重新计算

- 没有选中 SKU：计算当前仓库全部有效 SKU。
- 有选中 SKU：只计算所选 SKU。
- 页面显示即将计算的范围。
- 计算后更新日均出库、建议补货量、可售天数、预计缺货日期和状态。

## 10.6 删除信心度

彻底删除智能补货页面中的“信心度”列、数值、说明、提示和无效前端代码。内部质量指标如仍被其他逻辑需要，可保留后端字段，但不得展示或影响主要结果。

## 10.7 默认折叠

以下内容默认收起：

- 周期明细
- 补货参数
- 计算依据

用户展开状态只保留当前页面会话；刷新或重新进入后恢复收起。

# 12. 箭头与展开图标

检查全系统下拉、表格明细、折叠区、采购明细、平台代扣、智能补货等箭头。

不要求一刀切替换；原本美观的保持不变。以下情况必须修改：

- 锯齿明显

- 同类组件差异过大

允许不同用途有区别：

- 下拉选择器：小巧、朝下。
- 表格明细：朝右，展开后旋转朝下。
- 大区块折叠：可稍大但不抢眼。

优先使用 SVG 或 CSS 图标，不使用难看的字符箭头和浏览器默认图标。

# 13. 刷新登录状态

用户只要求同一浏览器标签页按 F5 或刷新时不退出，不要求关闭浏览器后保持登录。

验收要求：

- 刷新后恢复账号、组织、当前仓库、权限和基础页面状态。
- 只有 refresh token 真实失效、账号停用、后端明确拒绝或用户主动退出时才返回登录页。
- 临时断网、服务器 500 或接口超时不得无提示清空会话。
- 应显示错误与重试入口。

当前代码已使用 `sessionStorage` 保存 refresh token，理论上支持同一标签页刷新；优先排查启动恢复流程、令牌轮换、刷新接口、异常处理和部署缓存，而不是直接改为长期 `localStorage` 登录。

# 14. 事务、幂等与权限

必须使用数据库事务：

- 调拨二次编辑
- 调拨商品增减
- 修改调入仓
- 部分收货
- 撤回收货
- 取消调拨
- 全局权重覆盖

- 重新计算补货

- 主账号规则修改与回滚
- 主账号汇率修正
- 调拨编辑、收货、撤回和取消
- 智能补货参数修改

操作记录至少包含操作人、时间、修改前后数据、关联单号、库存流水和必要原因。

# 15. 测试与验收

## 15.1 利润试算

至少覆盖：

- 交易手续费 3.78%，无 RM4.13 封顶。
- 买家运费进入交易费基数但不进入商品售价。
- 部分退款。
- 平台支持费单 SKU、多 SKU 分摊和尾差。
- BXP/非 BXP。
- 类目佣金调试正数、负数、零。
- 平台代扣明细之和等于主行总额。
- 零金额费用仍显示。

## 15.2 仓间调拨

至少覆盖：

- 草稿不扣库存、可编辑和删除。
- 发出后扣减库存。
- 在途新增/删除商品和增减数量。
- 库存不足时整次回滚。
- 修改调入仓。
- 部分收货和多次收货。
- 单次收货撤回。
- 库存不足禁止撤回。
- 已调入撤回。
- 部分调入取消剩余数量。
- 状态筛选。
- 重复请求不重复记账。

## 15.3 智能补货

至少覆盖：

- 默认 40/30/20/10。
- 权重不等于 100% 禁止保存。
- 全选覆盖当前仓库全部有效 SKU。
- 未选中计算全部，选中只计算所选。
- 全局覆盖当前仓库，不影响其他仓库。
- 全局覆盖二次确认。
- 信心度删除。
- 次要信息默认收起。

## 15.4 登录

至少覆盖：

- 登录后 F5。
- 不同模块和仓库下刷新。
- access token 过期但 refresh token 有效。
- 短暂断网、后端 500、refresh token 失效和主动退出。

## 15.5 最终交付标准

任务只有在以下条件同时满足时才可标记完成：

- 页面实际显示正确，不受旧静态资源缓存影响。
- 所有按钮、保存、筛选、展开和收起均可操作。
- 所有业务操作有真实后端结果。
- 库存不重复扣减、不重复增加、不产生负库存。
- 调拨和库存流水可追溯。
- 费用规则与当前有效官方规则一致。
- 主账号权限后端有效。
- 汇率自动更新、手动刷新和手动修正可用。
- F5 刷新不退出登录。
- 已完成的导航顺序和删除新增商品按钮不回退。
- 自动测试与浏览器回归测试通过。
- PR 描述逐项列出：已完成、未完成、测试结果、已知限制和分支来源。
